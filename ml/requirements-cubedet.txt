# The permissive detector's own stack: what ml/cubedet trains with, what ml/test_cubedet.py needs,
# and what ml/export.py needs to write the ONNX artefact. This is the whole stack: PyTorch,
# torchvision, and the tools that write the artefacts. Nothing else trains the detector.
#
# Pinned to the environment that exported the shipped model (ml/models/MANIFEST.json `tools`).
# The training itself ran in the NGC image instead (MANIFEST.json `training_environment`), which
# brings its own torch and torchvision builds and has timm seeded beside it (ml/run-cubedet.sh).
#
#   python3.11 -m venv ml/venv-cubedet
#   ml/venv-cubedet/bin/pip install --extra-index-url https://download.pytorch.org/whl/cpu -r ml/requirements-cubedet.txt
#
# The extra index matters on Linux only: without it pip takes the CUDA build of torch, gigabytes of
# libraries for tests that never touch a GPU. `2.13.0+cpu` satisfies `==2.13.0`. macOS wheels come
# from PyPI either way. For all four artefacts, install ml/requirements-export.txt instead.
torch==2.14.0
torchvision==0.29.0
timm==1.0.30
# CAPPED BY PYTHON, not by tensorflow any more. The <2.2 ceiling this pin used to carry was
# tensorflow 2.19.0's (`numpy<2.2.0,>=1.26.0`); 2.21.0 asks only for `numpy>=1.26.0`, so the pair
# pip used to refuse now resolves. What still binds is the interpreter: numpy 2.5 requires Python
# >=3.12 and every ml job here runs 3.11, so 2.4.6 is the newest that installs at all — Dependabot
# proposed 2.5.3 and the golden harness could not install it.
#
# The shipped model was trained under numpy 2.1.0 (MANIFEST.json records it), so a checkpoint
# produced after this bump records a different environment than the one on disk. That is the point
# of recording it; it is not a reason to hold the version back.
numpy==2.4.6
pillow==12.3.0
onnx==1.23.0
onnxruntime==1.30.0
pytest==9.1.1
